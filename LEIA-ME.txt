BOTOES (dois cliques)
  ATUALIZAR_TUDO.bat              tudo: Sienge + obras + planilhas do BI + SQLs
  ATUALIZAR_SO_SQL.bat            so os SQLs (usa o raw que ja esta no BigQuery)
  ATUALIZAR_PLANILHAS_60_DIAS.bat so as planilhas (BI + InserirDados) + SQLs.
                                  O BigQuery apaga tabelas com 60 dias; as de
                                  planilha (db_perfomados, situacoes, contas
                                  bancarias, cobranca 3P...) so eram carregadas
                                  com --com-planilhas e sumiam. Rode quando
                                  aparecer "Not found: raw.xxx" no log.
  AGENDAR_TODO_DIA.bat            (uma vez) agenda ATUALIZAR_TUDO todo dia 05:00
                                  e ATUALIZAR_PLANILHAS_60_DIAS todo domingo 06:00
  tirar_validade_60_dias.py       depois de ATIVAR O FATURAMENTO do projeto no
                                  Google Cloud: tira o prazo de 60 dias de vez
                                  (python tirar_validade_60_dias.py)

  Se o Sienge der erro so numa parte (ex.: Clientes) mas o A Receber e as
  Recebidas forem carregados no dia, os SQLs rodam assim mesmo (aviso no log).
  cri_excel.py NAO roda mais nas planilhas (Excel parado desde 2025; o raw.cri
  vem do cri_extranet_bigquery.py).

ORDEM (o ATUALIZAR_TUDO.bat ja faz nesta ordem)
  1.  Dados do Sienge  -> sienge_rapido.py (deste pacote), com as funcoes
        dos scripts de InserirDados\AtualizacaoDiaria (nada muda neles)
        raw.clientes, raw.unidades, raw.vendas, raw.areceber,
        raw.recebidas_historico, raw.recebidas_atualizavel
        as 6 cargas AO MESMO TEMPO; cada tabela so e trocada no final, se
        a carga inteira deu certo (erro no meio = tabela anterior fica).
        Para voltar ao jeito antigo: python atualizar_tudo.py --sienge-original
  1b. Unidades das vendas -> AtualizarVendasUnidades.py (raw.vendas_unidades)
  1c. Telefones -> o script do InserirDados que carrega raw.clientes_telefones
  2.  Obras -> InserirDados\Obrasatt.py (raw.pagas_obras, raw.planejamento_obras)
  2b. Planilhas do BI (pasta cargas_planilhas_BI deste pacote)
        nome_companhias.py              9. BI\BI\Nome_Companhias.xlsx
        reparcelamento_analise.py       9. BI\BI\Bases_API\Extratos\EXTRATO_GERAL_Reparcelamento_Analise.csv
        distratos_controle_operacoes.py 9. BI\BI\DISTRATOS - CONTROLE OPERAÇOES.xlsx
        (os MESMOS arquivos que o Power BI le)
  3.  SQLs -> executar_pipeline.py + sql_bigquery deste pacote
        todos os .sql, na ordem das dependencias (arquivos independentes
        rodam juntos). Se a etapa 1 falhar, os SQLs NAO rodam (o raw
        fica pela metade e estragaria as tabelas) - rode de novo.
  Depois: no Looker, "Atualizar dados" (ou espera o cache de ate 12h)

  Opcional (outras planilhas do InserirDados):
     ATUALIZAR_TUDO.bat --com-planilhas
     situacoes, classificacao_bloko_niveis, nome_companhias_pag,
     comparativo (db_perfomados.py), cri, contas_bancarias, cobranca3p,
     linhas_temporais_geral
  So os SQLs:
     ATUALIZAR_TUDO.bat --so-sql

NO EC2
  1. Copiar a pasta BigQuery_Financeiro inteira (com InserirDados e este pacote)
     e a planilha Bases_API\Obras\Empreendimentos.xlsx
  2. Colocar o credencial_bigquery.json (conta de servico) na AtualizacaoCompleta
  3. Linux: bash instalar_ec2.sh  (instala, confere e agenda 05:00)
  4. Conferir a qualquer hora: .venv/bin/python conferir_ec2.py
  As planilhas do BI (etapa 2b) so existem no computador com o SharePoint:
  no EC2 essa etapa e pulada sozinha e os SQLs usam a ultima carga delas.
